# SEO and answer-engine audit — September 6, 2026

Repository: `enzo-prism/rebellious-aging` · Vercel: `ra-nextjs` · Canonical site: https://www.rebelwithsuz.com

## Findings and changes

| Finding | Change |
| --- | --- |
| Production `/nutrition` returned a 23-character loading message in its main content, with no H1 or FAQ schema before JavaScript. | Move Suspense to the interactive tabs. The heading, introduction, original educational sources, internal links, visible FAQs, and a default explanation now ship as HTML. |
| Generic titles such as “Blog,” “Style,” and “Nutrition” gave little topic context. | Descriptive titles for 18 static pages, retaining the established concise title policy and homepage brand title. Update homepage and guide descriptions. |
| Blog Open Graph dates used ambiguous US date strings; schema used timezone-dependent sorting timestamps. | A shared publication-date helper emits calendar dates only when the source specifies a day. All three surfaces—visible dates, Open Graph, and Article schema—agree. Month-only archive records do not invent a day or sitemap modification date. |
| Article author was an unlinked name; bylines and publication dates were not consistently visible. | All 100 public articles have an author profile link, available publication date, reading time, existing editorial excerpt, and an article landmark. |
| Separate organization/site schema objects lacked stable identity links. | Stable Organization, WebSite, and Suz Person IDs in the root layout. Articles reference those entities. Our Story identifies Suz as its main entity. The Facebook identity now uses the same real group URL as the navigation, and Suz’s profile links to her existing Substack. No medical license, review, or unsupported credential is invented. |
| Content hubs lacked collection markup; detail pages lacked breadcrumb markup. | Add CollectionPage/ItemList to blog, recipes and guides; visible breadcrumbs and matching BreadcrumbList on key hubs, pillars, articles, recipes and guide details. |
| Nutrition FAQ markup described questions that were not actually presented as a FAQ section. | Shared data generates both visible answers and JSON-LD for nutrition and homepage FAQs. |
| Recipe schema defaulted to Suz as creator and the site logo as the food image, including recipes credited to outside sources. | Preserve original source citations. Distinguish credited people and organizations; omit unknown creators and book titles from author markup. Never describe a logo as a completed dish. |
| The nutrition introduction made broad disease-reversal claims without an attached source. | Replace the broad claim with a descriptive introduction and direct links to the original educational resources. Preserve Suz’s personal stories. |
| Animation classes hid Our Story when JavaScript was disabled. | A noscript style keeps animated editorial content visible without JavaScript. |
| Existing `llms.txt` was mostly a short list of bare URLs. | Generate descriptive links to pillars, guides, all public articles and recipes, plus community definitions. Continue excluding password-gated articles. |
| Named search-bot rules bypassed generic private-path exclusions. | Let search and answer-engine crawlers inherit the existing wildcard allow rule and exclusions. Preserve the existing explicitly blocked SEO scrapers. |
| Search preview settings did not explicitly permit large image previews. | Add Googlebot large-image, unrestricted snippet, and unrestricted video-preview directives to indexable pages. Preserve existing noindex routes. |
| Generated diagnostic/search JSON could become search landing pages. | Add Vercel noindex response headers for those resources. |
| The apex domain used a temporary 307 redirect to www. | Production release changes the existing Vercel domain redirect to permanent 308, preserving the canonical destination. |
| The old metadata audit checked configuration rather than the HTML actually exported. | Add `npm run audit:seo` to every build. Audit all sitemap pages, titles, descriptions, canonicals, Open Graph URLs, main headings, readable bodies, author dates, matching FAQs, collection links, breadcrumbs, local links/assets, and noindex utility pages. |

## Validation

- Export audit covers 157 indexable routes, 100 public articles, two visible FAQ sections, and 168 unique local link/asset destinations.
- Unit tests include entity references, attribution safeguards, ISO recipe durations, breadcrumbs, and publication-date precision.
- Browser tests explicitly disable JavaScript to verify nutrition content, homepage answers, the author story, and article bylines.
- `npm run readiness:verify` passed: typecheck, lint (0 errors; 26 existing image warnings), build, 73 unit tests, and 98 browser tests.
- All six production-export performance tests passed the repository’s LCP/FCP ≤ 2.5 seconds, CLS ≤ 0.1, and interaction/blocking-time thresholds. These are local laboratory checks, not field Core Web Vitals.
- The final unit coverage gate passed: 85.15% lines, 90.9% functions, 60.59% branches, and 82.31% statements.
- Raw production samples before the change are saved in `baseline-2026-09-06.json`.

## Remaining editorial and measurement opportunities

- The recipe data has no original completed-dish image URLs. Google requires a representative dish image for recipe rich results. Add rights-cleared photographs to `Recipe.image` and descriptive `imageAlt` values when available. The implementation intentionally omits misleading image markup instead of fabricating eligibility.
- Month-only archive dates cannot be made more precise without editorial evidence. Do not fabricate publication or modification dates.
- FAQ markup does not guarantee a Google FAQ rich result. Google restricts that feature to qualifying authoritative government/health sites; the visible answers are useful independently.
- `llms.txt` is supplementary. Google says no special AI text file or AI schema is required for AI Overviews/AI Mode. Crawlable, helpful, attributable content is the priority.
- Search Console indexing, search impressions, click-through rates, and eventual answer-engine citations require post-release observation. Technical verification does not establish rankings or guarantee inclusion.
